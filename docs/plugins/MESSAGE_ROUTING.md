# 插件消息路由

插件通过 `Plugin::service_config()` 声明命令入口，管理员可在 Dashboard 插件页的「使用设置 → 命令前缀」中调整。前缀是插件的消息命名空间：先判定消息归属哪个插件，再由该插件匹配具体功能。自动解析链接等被动功能需另行声明自动监听，不能借助普通规则绕过命令前缀。

```rust
fn service_config(&self) -> Plugins {
    Plugins::new(self.name()).with_prefix(vec!["url".to_string()])
}
```

以上插件可以注册业务命令 `QQ音乐登录`，用户发送 `urlQQ音乐登录` 或 `urlqq音乐登录`。命令声明只写业务名称，不能把 `url` 再写进命令名称或正则；修改插件前缀后，入口随配置一起改变。

## 选择插件

- 存在非空有效前缀时，命令、前缀/后缀/关键词/全匹配/正则规则、`Message`、`File` 和 `on_event` 消息回调都必须命中命令前缀。裸链接和分享卡片仅能通过显式声明并启用的独立自动监听进入插件，不能用普通规则绕过前缀。
- `prefix` 和未被禁用的 `force_prefix` 共同提供可选入口。`force_prefix` 是历史字段名，界面显示为「额外前缀」，它与普通前缀并列，不要求用户连续输入两层前缀。`disable_force_prefix=true` 只关闭额外入口。
- 前缀匹配忽略 ASCII 大小写，多个前缀取最长匹配，不依赖配置顺序。不同插件声明相同前缀时不能靠插件加载顺序决定归属，冲突消息拒绝派发。
- 没有有效非空前缀的插件直接匹配正文，但不能接收已被其他插件前缀认领的消息。旧 `allow_empty_prefix` 仅保留配置和 API 兼容，不再影响路由，也不能绕过非空前缀。
- 命中前缀后仍须通过插件开关、群开关、作用区域、权限和黑白名单校验。前缀认领只确定目标插件，不保证子命令存在或用户拥有执行权限。
- 框架保留已有的 `nuono` 核心指令入口和 `/ai ` Agent 入口。即使插件配置了 `/` 等覆盖前缀，这些消息也优先交给框架；`/ai ` 仍沿用小写加空格的现有语法，不进入插件或等待回复回调。

例如配置查询插件为 `demo`、解析插件为 `url` 后，`demo帮助` 交给查询插件，`url帮助` 交给解析插件。配置前缀为 `parse` 后，解析插件入口统一变为 `parse`，业务处理器无需再维护一份入口配置。

## 匹配正文与保留原始事件

框架的命令和规则匹配使用去插件前缀后的正文。命令名与命令别名忽略 ASCII 大小写，参数保留输入内容；正则自身的大小写、锚点和捕获组仍按正则声明处理。需要单独的规则前缀时，它位于插件前缀之后，只能进一步限定插件内部功能，不能另开一个绕过插件入口的通道。

原生回调通过 `Event::command_text()` 读取供业务解析的正文，通过 `Event::command_prefix()` 读取本次识别到的插件前缀。`Event::text()`、`Event::raw()`、消息段和平台原生事件保留原始内容；参数提取与命令识别不能继续手动从原始文本剥离固定的 `demo`、`url` 或 `/`。保留原始事件便于读取图片、附件、引用以及完整的平台身份。

```text
用户输入： urlQQ音乐登录 SomeToken
业务正文： QQ音乐登录 SomeToken
原始文本： urlQQ音乐登录 SomeToken
```

命令、规则和 SV 声明的 `priority` 仍用于候选规则排序，数字越小越先执行；带规则前缀的规则仍优先。`block` 继续控制匹配后的传播，处理失败也按该规则的 `block` 决定是否停止。不再提供插件级优先级。

## 每插件触发保护

管理员在插件页的「触发保护」分别设置用户冷却、用户进行中任务上限和群额度。它们是宿主管理策略，不是业务配置字段，也不随群业务配置覆盖。

| 字段 | 默认值 | 范围与含义 |
| --- | --- | --- |
| `user_cooldown_ms` | 1000 | 0–3600000 毫秒；同机器人、同会话内，该用户在此插件中两次获准请求的最短间隔，0 关闭 |
| `max_in_flight_per_user` | 1 | 0–32；同机器人、同会话内，该用户在此插件中的进行中请求上限，0 关闭 |
| `group_requests_per_minute` | 30 | 0–60000；每群每分钟补充的令牌数，0 关闭群额度 |
| `group_burst` | 3 | 1–1000；群令牌的初始容量与最大积攒容量 |

用户冷却与进行中请求按「同机器人、同会话、同用户、同插件」隔离：同一用户在不同群和私聊中独立计数。群额度使用随时间补充的令牌桶，不在整分钟突然清零。默认可连续接纳 3 次请求，之后平均每 2 秒补充一次；同机器人、同群所有用户共享该插件的群额度。私聊只检查对应会话中的用户限制。用户和会话身份包含平台、机器人路由及原生身份，不把不同平台的同名 ID 合并。

只有通过权限、开关和路由检查的明确插件前缀入口、已命中的自动监听、已匹配的命令或规则才申请额度。没有匹配入口的普通聊天不消耗额度。同一插件在同一条消息中的 `on_event` / 自动监听回调和后续多个触发器共用一次准入结果，不重复扣费。空前缀插件原始 `on_event` 的探测回调不扣额度；需要受统一保护的业务入口应声明命令、规则或监听范围，不把任意聊天处理隐藏在探测回调中。

未获准的请求不进入业务处理，也不积压为等待额度的队列。自动监听和前缀事件回调被拒时静默继续；若有实际匹配的触发器，会给出简短提示，同机器人、会话、用户、插件 10 秒内最多一次。拒绝仍按匹配规则原有的 `block` 决定传播，不把所有限流都变成 `Stop`。等待回复的已建立会话不再次申请额度，权限、黑白名单和插件开关仍按下面的会话规则复核。

OneBot 排队消息使用收到时记录的单调时刻检查用户冷却；用户并发上限为 1 时，在上一项尚未完成时已经提交的重复请求，不会因为轮到执行时上一项刚结束就重新获准。

命令通过 SDK `ctx.spawn` / `tasks.try_spawn` 派生同插件受管任务时，进行中请求会保留到所有这些任务及其受管后代结束。受管绘图和浏览器阻塞工作也会保留到实际工作结束，取消等待不提前释放。裸 `tokio::spawn` 不自动继承这份租约，插件不应依靠它绕过进行中任务上限。在 `on_enable` 注册的定时任务、工具调用及非消息事件不从聊天额度扣费。

策略保存到数据库 `nuono_plugins.trigger_policy`，提交成功后新准入立即使用新值；不重载插件，不触发业务配置回调。保存保留已有冷却、群令牌和在途租约，不补满群额度，也不取消正在进行的请求。次数和令牌只在本进程的有界内存状态中保留，重启后重新开始。

## 会话与非消息入口

等待会话按完整的平台、接入实例、机器人原生 ID 及会话、用户、插件身份隔离，同一账号在不同实例中的等待互不消费。已建立的等待回复会话仍可接收不带前缀的回答；显式带插件前缀的消息会转交目标插件，不会被等待会话拦截。新命令入口仍须遵守前缀规则。

OneBot 普通业务消息继续按连接串行处理，已登记等待的回复走独立准入路径交付，因此命令内可直接 `await bot.wait_for_reply(...)`，无需为放行下一条回复自行派生后台任务。等待登记会通知调度器重新检查有界队列，覆盖回复已先入队的情形；API echo 仍由 socket reader 单独接收。入站通道及待处理队列上限各为 100 条，积压超限时记录过载并关闭连接，不无限创建消息任务。

交付前会重新校验全局过滤、用户权限、插件权限与作用范围、黑白名单及群开关；通知和请求事件不能消费消息等待。宿主为命令 Bot 和插件上下文 Bot 绑定插件归属；未绑定归属的独立 Bot 不能直接等待聊天回复。需保留回复的原生身份和语言时使用 `wait_for_reply_event`。业务数据库事务应在收到回复并完成校验后再开启，避免跨用户交互期间长期占用连接。

`InteractiveSession::send_and_wait` 和 `WaitReply` 在发出提示前先登记等待；发送失败、超时、取消或 future 被丢弃时自动清理自身登记。直接控制提问流程时可先调用 `Bot::prepare_reply_wait` 登记。每次登记拥有独立代次，被替换的旧任务不会误删新等待。插件禁用会取消在途等待并拒绝新登记；OneBot 连接断开会取消该连接关联的等待与后台回复流程。Dashboard 的会话列表和计数直接来自实际等待器，删除会话会唤醒等待方并返回取消错误。

宿主所有插件共用最多 1024 个待回复登记。`Bot::prepare_reply_wait`、`prepare_reply_event_wait`、`wait_for_reply` 和 `wait_for_reply_event` 在满额时返回 `Overloaded`，不覆盖其他会话；同会话替换不额外占登记额度。独立使用 `WaitManager` 或 `Waiter` 时优先调用 `try_register_*` / `try_register`，旧的无返回错误登记接口在拒绝时返回已关闭的接收对象。

`WaitReply` 后台等待使用插件现有受管任务额度（每实例 256 个），满额不会先发出提示。等待的绝对期限包含提示的准备和发送，挂起的发送在超时、取消或替换时也会退出。SDK 用 `Timeout` 区分超时、用 `Conflict` 表示取消或插件停用；直接 `.await` 接收对象仍保留原有 oneshot 错误类型。调用 `receive_result` 可取得上述类型化结果，`receive` 保留 `anyhow::Result` 兼容接口。零期限和溢出期限会被拒绝。

通知、生命周期等非消息事件没有可供匹配的聊天前缀，不受此路由限制。工具调用、定时任务沿用各自的授权、插件开关和执行规则，不要求拼接聊天指令。

`EventBus::MessageReceived` 是消息发布后的观察接口，仍携带原始事件，不能用它另建聊天指令入口。需要响应用户功能请求时，应注册命令、规则或使用 `on_event`；被动功能使用下面的监听入口，由宿主执行统一路由。源码插件与宿主同权限，前缀路由是一项调度契约，不提供沙箱隔离。

## 独立自动监听

框架提供监听机制，插件通过 `message_listener()` 声明范围并在 `on_message_listen()` 处理。文本正则和消息段类型任一匹配即进入范围，只有 `post_type=message` 可以监听；没有范围的声明会拒绝加载。正则在加载时编译，派发不重复执行声明。

```rust
fn service_config(&self) -> Plugins {
    Plugins::new(self.name()).with_prefix(vec!["url".into()])
        .with_auto_listen_enabled(true)
}
fn message_listener(&self) -> Option<PluginMessageListener> {
    Some(PluginMessageListener::new("链接和分享卡片")
        .with_text_pattern(r"(?i)https?://").expect("static pattern")
        .with_segment_types(["json"]))
}
async fn on_message_listen(&self, event: &Event) -> Result<PluginResponse> {
    // 在此解析 event.text() / event.message()；宿主保留原始内容。
    Ok(PluginResponse::Continue)
}
```

自动监听仅接收没有显式前缀归属的消息：`demo帮助` 不会被解析插件旁听；`url https://…` 走解析插件命令入口，直接链接/JSON 卡片走监听入口。同一插件同一消息最多选择一个回调，匹配监听且开关开启时选监听，否则保留原有命令门控的 `on_event`。空命令前缀仍允许直匹配命令，应使用监听声明实现被动功能。

监听同样经过权限、区域、黑白名单、事件类别与全局/群插件开关，沿用现有诊断和响应传播语义。`Continue` 继续后续插件及触发器，`Stop` / `Reply` / `WaitReply` 按原契约阻断；监听失败或 panic 捕获后继续。命令/规则的 `priority`、`block` 和管线顺序不变。

支持监听的插件在「使用设置」中显示独立开关。`auto_listen_enabled` 是框架保留配置键，业务 `config_fields()` 不得占用。未指定时默认关闭，链接解析类插件可显式声明默认开启。运行差异保存在数据库；未覆盖字段读取代码默认值，已保存的 `false` 保留。配置不能授予代码中未声明的监听能力。群设置逐字段继承，可覆盖监听开关，但插件全局禁用始终优先于群级设置。关闭自动监听后，带前缀的命令仍正常可用。

## 迁移已有插件

1. 在 `service_config()` 声明默认前缀，通过宿主配置统一管理入口。
2. 将命令名、别名和正则中的插件前缀移除，只声明业务正文的匹配方式。
3. 将 `on_event` 等回调中用于命令解析的 `Event::text()` 改为 `Event::command_text()`，移除硬编码的前缀剥离。读取原始消息、媒体或身份时继续用原有接口。
4. 检查更换前缀、ASCII 大小写、裸命令、裸链接、权限拒绝、跨插件消息、等待回复，以及规则 `priority` / `block` 的行为。完整的原始消息与参数不能因路由被改写。

前缀属于宿主声明的服务配置，全局差异保存在 `nuono_plugins.service_config_json`，对象差异保存在 `nuono_plugin_overrides`，与其他配置共用版本校验和消息快照。已有显式前缀保持不变，包括 `/`；插件默认值只用于未覆盖字段，不根据内容猜测并改写旧配置。需要换入口时由管理员明确修改。
